In compilers, linters, and macro expanders, every AST node and token carries a source span. When spans hold `PathBuf` clones or heap-allocated file names, memory usage climbs fast and passing locations across threads gets noisy.

Sourcier (`0.1`) registers each source file once and packs the file ID, line, and column into a single `Copy` `u64`.

## The Goal

We needed a lightweight source map for diagnostics-heavy Rust tools that hands out compact numeric file IDs, resolves 1-based line and column coordinates on demand, and lets spans sit inside AST nodes without lifetimes or heap allocations.

## How it works

A central source registry interns each file path and content buffer once, returning a compact `FileId`. Every `Span` bit-packs that ID alongside line and column offsets into one 64-bit integer.

## What it cost

Packing file IDs, lines, and columns into 64 bits means trading arbitrary integer width for fixed bit budgets. We had to define explicit bit widths for each field so standard source files pack without overflow while still catching out-of-range coordinates cleanly.

<Aside type="caution" title="Where this does not apply">
Because coordinates are bit-packed into a fixed `u64` layout, Sourcier is designed for normal source files rather than multi-gigabyte generated blobs with millions of lines in a single file. If your input exceeds the bit budget of a field, use full `usize` byte ranges instead.
</Aside>
