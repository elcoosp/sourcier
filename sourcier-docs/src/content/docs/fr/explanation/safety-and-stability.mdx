Sourcier fait des promesses sur lesquelles les outils peuvent construire : pas de code unsafe, une API stable et vérifiée par semver, et un comportement épinglé par des tests basés sur les propriétés, les instantanés et vérifiés par la couverture. Cette page explique chaque garantie et comment elle est imposée.

## Pas de code unsafe

Tout l'espace de travail porte `#![forbid(unsafe_code)]`. Chaque garantie de la crate — bit packing, sondage d'index, vues zéro-copie — est exprimée en Rust sûr. Il n'y a aucun bloc unsafe à auditer, et le compilateur rejette toute introduction.

## Traits scellés et erreurs non_exhaustive

Deux décisions au niveau des types empêchent les futures versions de casser votre code :

- **Le trait `FileId` est scellé.** Ses seules implémentations sont `u8` et `u16`, et le module de scellement rend impossibles les implémentations en aval. De nouvelles méthodes avec implémentations par défaut peuvent donc être ajoutées au trait dans une version mineure sans casser de code en aval.
- **Les énumérations d'erreur sont `#[non_exhaustive]`.** `MapError` et `PositionError` peuvent gagner des variantes dans des versions mineures sans changement cassant le semver. Les branches de match hors de la crate incluent une branche attrape-tout ; le compilateur l'impose.

## Politique semver

L'API publique documentée sur docs.rs est stable et suit le versioning sémantique à partir de 2.0.0. Deux précisions à connaître :

- Les layouts `u64` compactés sont documentés pour que les valeurs brutes puissent être persistées ; ils sont stables à travers les versions compatibles semver. Voir [Encodage des positions](/reference/position-encoding/).
- Le format filaire de la 2.0 a supprimé la table redondante `path_to_id`, et les payloads 1.0 qui portent encore le champ se désérialisent sans erreur — la compatibilité ascendante est explicite et testée.

## La suite de tests en couches

Le dépôt livre des tests unitaires, d'intégration, basés sur les propriétés, d'instantanés et de doc :

| Couche | Outil | Épingle |
| ----- | ---- | ---- |
| Unitaire et intégration | `cargo test` / `cargo nextest run` | Comportement par module, flux de builder et de navigation |
| Basés sur les propriétés | `proptest` | Aller-retours d'encodage de position, mapping inverse ligne/col vers offset, cohérence de lookup de map, résolution de doublons premier-enregistrement-gagne à l'échelle de centaines de fichiers |
| Instantanés | `insta` | Instantanés YAML de sérialisation de map, extraction de vue, positions compactées et messages d'erreur |
| Tests de doc | `cargo test` | Chaque exemple de code dans le rustdoc compile et s'exécute |

La suite de propriétés couvre aussi les maps désérialisées adversariales qui dépassent la capacité d'ids, et la limite d'offsets de ligne de 4 GiB est exercée de bout en bout avec des allocations à commit paresseux, donc les chemins de fichiers surdimensionnés sont testés pour de vrai.

Les fichiers d'instantané vivent dans `sourcier-core/src/tests/snapshots/` et sont commités ; régénérez-les après un changement intentionnel avec `INSTA_UPDATE=always cargo test`.

## Couverture et vérifications statiques

La CI exécute le portail complet :

<Code lang="bash" code={`cargo test --workspace --all-features      # tests unitaires, d'intégration, de propriété, de doc
cargo nextest run --workspace --all-features
cargo llvm-cov --workspace --all-features --summary-only
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo fmt --all -- --check
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps
cargo deny check                           # licences, avis, interdictions, sources`} />

La couverture mesurée avec `cargo-llvm-cov` rapporte 100 % de fonctions couvertes ; `llvm-cov show` confirme que chaque ligne et chaque région atteignable s'exécute. Le tableau récapitulatif rapporte 99,9 % pour les lignes et régions — les comptes résiduels sont des artefacts de compilateur inappelables (copies au site de définition de code générique), pas des tests manquants.

`missing_docs` est dénié à l'échelle de l'espace de travail, donc chaque élément public porte de la documentation, et rustdoc se construit avec les avertissements déniés.

## Le contrat MSRV

La version minimale supportée de Rust est 1.99, vérifiée en CI avec `cargo check` à travers les configurations de fonctionnalité. La crate utilise l'Édition 2024.
